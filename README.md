# СБОРКА

Одностраничный учебный каталог комплектующих с интерактивной 3D-сборкой компьютера.

## Возможности

- Восемь категорий, поиск, сортировка, характеристики и выбор компонентов.
- Вращение и приближение ПК, открытие боковой стенки, включение вентиляторов и RGB.
- Цвета компонентов, анимация установки, три режима подсветки.
- Основные проверки совместимости и ориентировочное потребление.
- Регистрация и вход по ссылке из письма через Supabase Auth.
- Роли клиента и администратора с проверкой прав в PostgreSQL.
- Сохранение, открытие, переименование при сохранении и удаление личных сборок.
- Админ-панель для создания, редактирования и скрытия товаров.

3D-модели создаются программно и имеют упрощённую геометрию. Внешний вид конкретных моделей и характеристики нужно сверять с производителем. Начальный каталог содержит демонстрационные цены. Покупки и оплата отсутствуют.

## Запуск на ноутбуке

Установите Node.js LTS. В папке проекта выполните команды.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Без Supabase доступны 3D-сборщик и демонстрационный каталог. Черновик сохраняется в браузере, облачная авторизация при этом явно отмечена как неподключённая.

## PostgreSQL и авторизация

1. Создайте бесплатный проект в Supabase.
2. В SQL Editor последовательно выполните `database/schema.sql` и `database/seed.sql`.
3. Скопируйте `.env.example` в `.env.local`. Укажите Project URL и Publishable key. Старый публичный ключ `anon` также подходит.
4. В Authentication → URL Configuration задайте Site URL и разрешённые Redirect URLs. Добавьте точный локальный адрес и HTTPS-адрес GitHub Pages, включая путь репозитория и завершающий `/`.
5. Перезапустите локальный сайт. Зарегистрируйтесь через форму, откройте ссылку из письма в том же браузере.
6. Назначьте администратора через SQL Editor, подставив email зарегистрированного пользователя.

```sql
update public.profiles
set role = 'admin'
where id = (select id from auth.users where email = 'ваш-email');
```

После изменения роли выйдите и войдите снова. Кнопка панели администратора находится в профиле. Клиенты получают роль `client` автоматически и не могут изменить её через API. Доступ к чужим сборкам ограничен RLS. Для писем внешним пользователям может потребоваться настроить свой SMTP в Supabase, поскольку встроенная отправка имеет ограничения.

## Публикация на GitHub Pages

Весь исходный код и SQL размещаются в одном публичном репозитории. Работающая PostgreSQL размещается в Supabase.

1. Отправьте проект в ветку `main`.
2. Откройте Settings → Secrets and variables → Actions → Variables. Создайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`.
3. В Settings → Pages выберите Source → GitHub Actions.
4. Запустите workflow Publish GitHub Pages или отправьте новый коммит в `main`.
5. Добавьте полученный адрес сайта в настройки Auth проекта Supabase.

Publishable key публичный, доступ к данным контролирует RLS. Пароль PostgreSQL и ключ `service_role` используются только в доверенных средствах управления, в исходники и браузер они не попадают.

## Обновление цен DNS

В карточках начального каталога есть поиск товара в DNS. Примерные цены явно подписаны и не выдаются за актуальные предложения магазина.

Подготовлен сценарий `scripts/update-prices.js`. Он получает цену из открытого структурированного предложения `Product.offers` в RUB на конкретной странице DNS. Прямые ссылки вида `https://www.dns-shop.ru/product/.../.../` задаются через админ-панель. Поисковые ссылки не используются для автоматического сопоставления.

Для включения добавьте секрет `SUPABASE_SERVICE_ROLE_KEY` в GitHub Actions, переменную `DNS_PRICE_SYNC_ENABLED=true` и проверьте ручной запуск Update DNS prices. Ключ остаётся в Secrets и не участвует в сборке браузерного сайта. Сценарий обновляет цену и дату только при успешном чтении. При отказе, отсутствии цены или товара старые значения сохраняются. Одновременная правка администратора защищена проверкой `updated_at`.

Во время разработки DNS возвращал HTTP 401 на прямые запросы. Успешное получение актуальных цен пока не подтверждено. При таком ответе нужен доступный источник предложений или согласованная выгрузка, иначе остаётся ручное обновление в админ-панели. Цены зависят от региона, который также нужно согласовать при подключении источника.

## Проверка

```sh
npm test
npm run build
```

На защите удобно показать регистрацию клиента, сохранение сборки, повторное открытие после входа, изменение товара администратором и отказ клиенту в изменении каталога. Схема базы и начальные данные воспроизводимы из SQL.
